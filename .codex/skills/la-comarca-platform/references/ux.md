# Management UX conventions

The public site uses a restrained editorial visual system: deep blue, warm neutral surfaces, one accent, short hierarchy, responsive layouts, and reduced-motion support. Reuse its tokens and accessibility habits without making the CMS look like the public landing page.

The management shell should organize work by operational intent: dashboard, agenda/calendar, spaces or programs, people/participants, materials, operations, notifications, administration, and settings—only where the repository proves the module exists. A dashboard must show pending actions, upcoming activity, alerts, and shortcuts, not decorative counts.

Use tables for scanning, cards for summaries, calendars for time, and detail views for relationships/history. Every important record should support contextual actions, search/filter/sort, loading/empty/error states, destructive confirmation, keyboard focus, and responsive behavior. Prefer a related-record detail experience over duplicated CRUD forms.

Do not claim a feature is available when it is only specified, disconnected, or manually performed in Notion.
